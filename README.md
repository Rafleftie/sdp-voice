# SDP Voice — Hackathon Demo

## Setup

Install the dependencies and start the Flask app:

```powershell
python -m venv .venv
\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
\.venv\Scripts\python.exe app.py
```

Set private login emails/passwords in `.env` using the `DEMO_*` names from `.env.example`, and set a long random `FLASK_SECRET_KEY`. Keep `.env` local: `.env`, other private `.env.*` files, virtual environments, and the SQLite ticket database are ignored by Git. Never paste secrets into source code, commit them, or send them in chat. The app reads `.env` when it starts, so restart after changing it. If a key or password was ever committed or shared, rotate it.

The `.env.example` contains blank values only. Add new private login emails and passwords locally; logins are intentionally disabled until those values are set. Generate a session key in PowerShell with `[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))`, then put its output in `FLASK_SECRET_KEY`. Do not reuse the old demo passwords.

Server runs at http://localhost:5000

End users can type a request or dictate it with the browser microphone; stopping a recording automatically submits the recognized transcript as a voice ticket. They can view their own tickets, including tickets marked Closed, and receive in-app notifications when IT changes ticket status. Dictation uses browser speech recognition; the ticket stores the transcript, not an audio recording. Ticket email is taken from the signed-in account, not from submitted form data.

Ticket analysis runs on submission. The generated category, priority, and concise summary are shared between the end-user history and IT queue; both views also show the user's original description. IT also gets a suggested resolution, generated by Anthropic when `ANTHROPIC_API_KEY` is set or by local troubleshooting rules otherwise. Suggestions are advisory and should be reviewed before applying.

IT can assign tickets to either support account and filter by assigned-to-me, priority, and category. Technicians can rate each suggestion as helpful or not helpful. They can also click **Troubleshoot** on a ticket to ask follow-up questions using its description and current suggestion as context. Technicians can dictate follow-ups and optionally hear assistant replies read aloud. Anthropic generates replies when configured; otherwise the app provides local guidance. These controls are available to IT support only.

The **Ticket insights** page displays open, in-progress, resolved, closed, priority, and category counts. Its on-demand queue summary sends aggregate counts only to Anthropic when configured; without a key it uses a local summary and makes no API call.

The app stores tickets in `tickets.db` in the project folder.
